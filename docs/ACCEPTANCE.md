# 本地验收记录

## v0.4.0 额度明细、订阅和活动

Galaxy S24 和 Galaxy Watch7 使用同签名覆盖安装的 Debug 验收构建，保留了原有 Hub 配置。本轮使用真实 Token Monitor Hub，验收在本地进行。

| 验收项 | 结果 |
| --- | --- |
| S24 额度详情 | 点开账户卡片后，剩余走势显示实际额度观测。近 14 天的每日用量里已有根据可比较读数计算的日汇总。 |
| S24 订阅 | 从真实 Hub 读到共享订阅记录，核对了金额、续费周期和续费日期的实际值。 |
| S24 小时趋势 | 切换过去 12、8、4、2、1 小时。过去 1 小时的折线显示实测采样增量。 |
| Watch7 K 线配色 | S24 扫码发送「红涨绿跌」预设，核对 Watch7 的 30 天 K 线在下发前后的实际绘制颜色。强制停止并重新打开手表 App 后，配色保留，手表仍通过自身网络读取真实 Hub。本轮的重启验收范围为应用进程。 |
| Android 模拟器 | 用合成 Hub 数据对照额度明细和订阅字段，验证活动页的数据条、K 线配色、设备紧凑布局与拖动排序、关注额度两种样式及 App 重启后的设置保留。 |
| 本地 CI 与安装 | 22 项 Kotlin 单测、两端 Lint、Debug 和 Release 构建均通过。Android 与 Wear OS 模拟器分别完成同签名的 v0.3.0 Release 至 v0.4.0 Release 覆盖升级，并成功打开应用。 |

## v0.3.0 显示预设与 Watch7

Galaxy S24 和 Galaxy Watch7 通过无线 ADB 安装同签名 Debug 验收构建，保留了原有 Hub 配置。两端使用真实 Token Monitor Hub，全程在本地验收，未使用 GitHub Actions 或 ADB 转发。

| 验收项 | 结果 |
| --- | --- |
| 手机实时预览 | 拖动周期额度的工具顺序后，额度预览即时更新。趋势预览即时显示 30 天范围、每 7 天一个分桶和 K 线。 |
| 扫码下发 | S24 扫描 Watch7 的一次性配对码，手表确认应用显示预设。手表实际显示与手机设置的周期排序和趋势设置一致，OLED 背景为纯黑。 |
| App 重启 | 强制停止并重新打开手表 App 后，周期排序、趋势范围、采样间隔、K 线和 OLED 设置均保留。本轮只验收 App 重启。 |
| 独立直连 | App 重启后手动刷新，「本机取数」时间推进，手表继续通过 HTTPS 读取真实 Hub。 |

## v0.2.0 总览、趋势和额度

本版使用本地 CI 和合成 Hub 数据复验。历史样本覆盖 366 天，包含重复额度读数及同一工具的多种额度窗口。

| 验收项 | 核对点 |
| --- | --- |
| 时间范围与图表 | 总览与活动共用时间筛选。核对 7 天和 365 天的实际跨度，以及折线和 K 线切换。单元测试检查日内增量、空值、计数器回退、自然周／月／年边界和 K 线开高低收。 |
| 显示偏好 | 常用筛选最多固定四项。总览卡片可在展示队列中拖动，可移除后重新添加。额度和余额分别保存卡片顺序。 |
| 离线与手表额度 | 首页的 Hub 连接状态集中在顶部，已有快照时继续显示缓存。手表短时、周期和余额视图在各自类别内按工具和账号组织，重复窗口只保留一条。 |

### Galaxy S24 与 Galaxy Watch7 真机验收

两端通过无线 ADB，用与已安装版本证书相同的 v0.2.0 Debug APK 覆盖升级。Hub 配置和缓存均保留，两端通过 HTTPS 直接读取真实 Hub。

| 验收项 | 结果 |
| --- | --- |
| 时间范围和图表 | S24 总览和活动共用时间筛选，七种范围均完成切换。连续取数后，当日折线和 K 线均显示实测采样增量。 |
| 总览和额度排序 | 拖动保存后重启应用，卡片与账户次序均保留。验收后恢复原顺序。 |
| 断网缓存 | 使用 Android 防火墙做 App 级网络阻断，手机 Wi‑Fi 保持开启。重启 App 后，首页仅出现一条缓存提示，缓存用量仍可查看。解除阻断后成功获取新快照。 |
| 手表额度分组 | Watch7 使用自身 Wi‑Fi 独立直连。核对短时和周期窗口，同一工具在类别内以一个标题显示，并保留不同窗口。余额区暂无真实读数。 |

## v0.1.0 Android 与 Wear OS

| 验收项 | 结果 |
| --- | --- |
| 手机直连 | 真机通过 HTTPS 直接读取真实 Token Monitor Hub 的额度和用量。 |
| 扫码导入 | 在同一 Wi‑Fi 下，使用手机扫描手表的一次性配对码。手表验证手机发送的 Hub 配置后，手机收到确认，手表进入独立直连。 |
| 手表独立直连 | 关闭手表蓝牙并停止手机 App 后，手表通过自身 Wi‑Fi 刷新成功。电脑完全关机后，设备操作者再手动刷新并确认「本机取数」继续前进。使用真实 Hub，无需 ADB 转发或 Companion Server。 |
| 手机推送、远程 Hub 设置和模式切换 | 已系统配对的手机和手表模拟器通过 Hub 测试数据验证发现、用量转发、远程 Hub 设置和回执。测得两种模式可互相切换。这些 Data Layer 项目未在本轮真机环境复验，手机的 Wearable API 不可用。 |
| 扫码协议 | 本地测试覆盖二维码解析、拒绝消息篡改与重放，以及同一个配对码只接受一次有效发送。手机模拟器打开扫码相机，手表模拟器显示二维码。 |
| 本地 CI | 10 项 Kotlin 测试、两端 Lint、Debug 和 Release APK 构建通过。 |

设备明细、运行日志和截图保存在测试设备操作者的本地环境。
